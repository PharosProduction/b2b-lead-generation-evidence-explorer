Build a requirements draft

Choose a provider and a delivery object. Add the rule that will be applied, the receiving role, an evidence reference and an exclusion. This tool checks whether those four fields contain text. It cannot establish whether that text is correct or whether a provider accepts your requirements.

Review context

Use role labels and document references rather than personal contact data. Fields stay in this page's memory. Export before leaving or clearing the draft; nothing is saved automatically. Clear the draft before switching provider so one provider's evidence is not silently carried to another.

Fictional Pineharbor Labs review

Pineharbor Labs is an invented buyer preparing a research-only brief. It asks for a contact sample that matches a stated industry and role rule. Its internal research reviewer needs a sample reference to discuss acceptance. Sending outreach and booking meetings are explicitly excluded from this example.

The U-362 fictional requirements file supplies four example values. The inspector reports FIELDS_PRESENT_NOT_VERIFIED because text is present. That output does not establish list accuracy, legal permission to contact anyone, provider agreement or sales readiness. Removing the evidence reference changes the field state to FIELD_GAPS.

Do not turn the result into a provider score. A fully populated draft can still contain an outdated rule, the wrong document reference or a receiving role without authority. Those questions require a person to inspect the source and agree the working scope.

What this resource can establish

Selection
Ten named agencies with public B2B lead generation or adjacent sales development descriptions. This is a bounded editorial set, not an exhaustive market census.
Temporal scope
Descriptions checked on November 21, 2026. SalesRoads' official program-comparison article was read separately after direct homepage access returned HTTP 403. Offers can change after the check.
Ordering
TopClick first with disclosed affiliation, followed by nine alphabetical entries. No supplier quality, price or outcome score was calculated.
Runtime
Buildless HTML and JavaScript. Field inspection and JSON export run in the browser without a server submission, saved customer database or automatic outreach action.
Validation boundary
Four text-presence checks plus permitted provider and delivery choices. A syntactically usable draft is not verified evidence. Matching labels do not authenticate a source document.

Read the outputs precisely

FIELD_GAPS means at least one named field is blank after trimming spaces. FIELDS_PRESENT_NOT_VERIFIED means the four text fields are nonempty. Both results retain sourceSupportVerified: false, supplierApproved: false, outreachAuthorized: false and crmUpdated: false.

The export is a portable requirements draft. It has no signature, verified source capture, CRM connection or vendor-acceptance record. A fictional reference can pass the presence check just as a real reference can. Review the underlying evidence before relying on either.

Reproduce the checks

The repository includes the inspector, browser interface and deterministic boundary tests. With a current Node.js installation, run node --test tests/model.test.mjs from the repository directory. Tests exercise local field handling and guardrails; they do not test suppliers, campaigns or contact quality.
